# Ponzu

See [README.md](README.md) for the layout and [CONTRIBUTING.md](CONTRIBUTING.md) for the workflow.

- Run `bun run lint`, `bun run typecheck`, `bunx tsc -p apps/desktop/tsconfig.json --noEmit` and `bun test` before finishing.
- **Ride the happy path.** Reach for the standard, well-supported tool before writing our own: [shadcn/ui](https://ui.shadcn.com) components (added with its CLI, themed with our tokens) for UI elements, the [AI SDK](https://ai-sdk.dev) for model calls our services make, and a vendor's official SDK or the ecosystem's usual library for things like auth, GitHub, storage and data fetching. Write our own only when the standard tool can't do the job, and say why in the pull request.
- **A change users would notice ends its PR description with a `## Release note` section**: one plain sentence per change. The squash commit carries it into the desktop app's update popover and the iPhone's TestFlight notes; no section means no note. In a PR that changes both apps, prefix each note `Mac:` or `iPhone:`. See [docs/release-notes.md](docs/release-notes.md).
- **PR titles are Conventional Commits** with a lowercase description (`fix:`, `feat:`, `feat!:`); CI checks them. PRs are squash-merged, so the title is the commit Release Please reads.
- **Never edit version fields or push tags.** Release Please owns versions, for two components: the desktop app for Mac, Windows and Linux (`vX.Y.Z`) and the iPhone app in `apps/mobile` (`mobile-vX.Y.Z`). Each release PR merges itself; `.github/workflows/release.yml` builds and launches the desktop app on all three, signs and notarizes the Mac's, and publishes only once all three succeed, and EAS ships the phone (over the air, or a TestFlight build when native code changed).
- **The iPhone app** (`apps/mobile`, Expo): see [docs/mobile.md](docs/mobile.md). Never import `@ponzu/canvas` or `@ponzu/render` from it. `ios/` is generated; don't commit it. Native iOS builds and simulator runs follow `docs/mobile.md`.
- **Performance**: every pull request that can change the app gets a comment with the studio's performance harness, head against base ([apps/studio/perf](apps/studio/perf/README.md)). For a change to how the canvas, thread or panes draw, profile with it (`--profile`) and explain any number that moved in the PR description.
- **`.design` files**: [`design/`](design) holds only the public, lasting ones (brand, press kit, design system), and a change to what they show updates them in the same PR. Disposable exploratory designs made while developing go in `.context/`, which is gitignored.
- Packaging changes: `cd apps/desktop && bun run package:dir`, then `PONZU_SMOKE=1 out/mac-arm64/Ponzu.app/Contents/MacOS/Ponzu` must exit 0.
