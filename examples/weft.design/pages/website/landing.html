How it works

From npm install to multiplayer in an afternoon.

No sync server to run, no conflict resolution to write, no cache to invalidate. You define data and rules; Weft keeps every copy in agreement.

01
Define a schema

Collections, fields and CRDT types in TypeScript. Weft generates typed hooks and the Postgres tables.

weft.schema.tsTS
export default schema({ cards: { title: text(), // RGA lane: lww<Lane>(), votes: counter(), }, })
02
Write rules

Permissions live next to the data and run on every op, at the edge and on the server.

weft.rulesRULES
rule cards.update { allow: auth.uid in doc.board.members deny: doc.locked == true }
03
Ship it

One command deploys schema and rules to 14 regions. Your app keeps working through the deploy.

$ weft deploy ✓ schema 3 collections ✓ rules 14 compiled · 41ms ✓ regions 14/14 live → halyard-prod.weft.sh
Features

Everything between your UI and your database.

The parts every realtime app rebuilds, done once and done carefully.

Offline by default

Every read is local. Writes queue in the op log and replay on reconnect, in order, exactly once.

offline op_7Hk2pop_7Hk2qop_7Hk2r replayed · 3 ops · 41ms
Conflict-free merges

LWW registers, RGA text and counters. Concurrent edits converge on every device. No last-write-loses.

Presence

Cursors, selections and typing indicators with 2s batched heartbeats. Never touches disk.

Rules at the edge

Row-level permissions compiled to WASM, enforced on every op and every read.

It’s just Postgres

Query synced data with psql, Prisma or Drizzle. SQL writes become ops and sync to clients.
